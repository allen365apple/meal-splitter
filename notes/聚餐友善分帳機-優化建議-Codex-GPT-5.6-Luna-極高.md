# 聚餐友善分帳機｜優化建議

## 文件資訊

- 專案：聚餐友善分帳機
- 檢查方式：實際操作本機網頁，並搭配原始碼檢查
- 檢查範圍：成員、標籤、菜色輸入、計算機、文字匯入、分攤調整、結算、複製與安裝說明
- 文件撰寫模型：Codex GPT-5.6 Luna 極高

## 一、已實際測試的功能

- 成員新增、刪除、改名與切換標籤
- 群組標籤新增與刪除
- 手動新增菜色與金額
- 輔助計算機的加、減、乘、除、小數、清除、退格、等號與套用結果
- 全員、標籤群組與自訂成員分攤
- 菜色刪除與多項目時的收合標題列
- 文字貼上、AI 指令複製、批次匯入與收據摘要過濾
- 服務費率增減
- 個人明細展開、個人算式複製、全員結算單複製
- 返回修改
- 加入主畫面說明

## 二、需要優先修正的問題

### P0：取消所有分攤人會讓金額直接消失

實測方式：新增一筆 `$100` 菜色，將所有分攤人取消後進入結算。

實際結果：總金額顯示 `$0`，頁面沒有提示未分配金額。

原因位置：[index.html:234](/Users/allen365apple/Desktop/Claude-workspace/projects/聚餐友善分帳機/index.html:234)。目前只有 `sharerCount > 0` 時才會把項目金額加入 `subTotal`。

建議：

1. 不允許一道菜變成 0 人分攤，取消最後一人時顯示提示。
2. 或保留「未分配金額」區塊，讓使用者知道還有多少錢沒有分出去。
3. 刪除成員後也要檢查是否有菜色變成 0 人分攤。

### P0：四捨五入後，個人加總可能不等於總額

實測方式：三人分攤 `$100`，服務費 10%。

實際結果：總額為 `$110`，三人各顯示 `$37`，合計為 `$111`。

原因位置：[index.html:234](/Users/allen365apple/Desktop/Claude-workspace/projects/聚餐友善分帳機/index.html:234) 與 [index.html:541](/Users/allen365apple/Desktop/Claude-workspace/projects/聚餐友善分帳機/index.html:541)。目前各人的金額獨立四捨五入，沒有分配尾差。

建議：

- 以整數「分」計算，避免浮點誤差。
- 先計算總額，再用最大餘數法或指定規則分配尾差。
- 個人明細、服務費、全員結算單都使用同一套分配後的金額。
- 可在介面標註「尾差由某位成員吸收」或讓使用者指定尾差歸屬。

### P1：千分位金額匯入錯誤

實測輸入：

```text
牛排 $1,200
啤酒 60
```

實際結果：第一筆被解析成品名「牛排 $1,」、金額 `$200`。

原因位置：[index.html:178-192](/Users/allen365apple/Desktop/Claude-workspace/projects/聚餐友善分帳機/index.html:178)。目前金額正規表示式只允許逗號後最多兩位數，無法正確處理千分位。

建議：

- 先把 `$1,200`、`1,200 元` 正規化成 `1200` 再解析。
- 從每行最後一個金額開始解析，避免品名中的數字被誤判。
- 匯入後提供預覽，讓使用者在正式加入前修正品名與金額。

### P1：金額欄位允許 0 與負數

實測結果：輸入 `$0` 或 `-$50` 時，「加入清單」仍會啟用。

原因位置：[index.html:432](/Users/allen365apple/Desktop/Claude-workspace/projects/聚餐友善分帳機/index.html:432) 與 [index.html:467](/Users/allen365apple/Desktop/Claude-workspace/projects/聚餐友善分帳機/index.html:467)。目前只檢查字串是否為空，沒有檢查數值範圍。

建議：

- 金額必須是有限數字且大於 0。
- 在輸入欄加入 `min="0.01"` 與合適的 `step`。
- `addItem` 內再次驗證，不能只依賴 HTML 輸入限制。
- 計算機也要處理除以 0、無限大與非數字結果。

## 三、功能可靠性與使用體驗優化

### P1：複製成功狀態需要真正確認

目前使用 `document.execCommand('copy')`，而且沒有檢查它的回傳值；即使複製失敗，也可能顯示「已複製」。

實際測試中，按下「複製全員結算單」後再使用頁面內的「貼上」，仍貼回前一段測試文字。這可能與自動化瀏覽器的剪貼簿隔離有關，但正式環境仍應重新驗證。

原因位置：[index.html:235-237](/Users/allen365apple/Desktop/Claude-workspace/projects/聚餐友善分帳機/index.html:235)。

建議：優先使用 `navigator.clipboard.writeText()`，失敗時再使用 fallback；只有 Promise 成功時才顯示複製成功。

### P1：匯入流程應增加預覽與逐行錯誤提示

目前匯入成功後直接加入清單，且所有項目預設為「大家都有」。這雖然快速，但錯誤金額或錯誤品名會直接進入結算。

建議：

- 顯示解析預覽：品名、金額、預設分攤人數。
- 標出無法辨識的行與被忽略的行。
- 將「小計、總計、服務費、稅額」等排除規則擴充並改為不分大小寫。
- 提供「全部套用大家都有」與「匯入後逐筆確認」兩種模式。

### P1：資料應該能暫存或恢復

目前所有資料只存在 React state，重新整理頁面後成員、菜色與分攤結果都會消失。

建議：

- 使用 `localStorage` 暫存目前帳單。
- 提供「新增一桌／清空目前帳單」操作，避免上一桌資料殘留。
- 增加 JSON 或文字格式的匯出／匯入，方便跨裝置繼續編輯。

### P2：圖示按鈕缺少無障礙名稱

刪除、關閉、開啟計算機等圖示按鈕在無障礙樹中沒有可讀名稱。

建議：為所有圖示按鈕加入 `aria-label`、`title` 與清楚的鍵盤 focus 樣式；文字輸入框與下拉選單也應搭配 `<label>`。

### P2：刪除操作需要復原機制

成員、標籤與菜色都能直接刪除，目前沒有確認、復原或 Undo。

建議：優先加入短時間 Undo Toast；若不加入 Undo，至少在刪除成員或標籤時顯示影響範圍。

### P2：標籤刪除後要清理既有菜色狀態

刪除標籤時，成員會被改派到第一個標籤，但既有菜色的 `type` 與 `typeLabel` 可能仍保留已刪除的標籤資訊。

建議：刪除標籤時同步將相關菜色重新標記為「自訂名單」，或依新的成員標籤重新計算分配類型。

### P2：服務費率應有上限與更直接的輸入方式

目前只能每次增減 5%，且「+」可以無限增加。

建議：限制在 0% 到 100%，並允許直接輸入，例如 5%、10%、免服務費等常用選項。

## 四、技術與部署優化

### P2：目前不是完整 PWA

頁面有加入主畫面說明和 Apple touch icon，但沒有 `manifest`，也沒有 service worker。Android 可能不會出現真正的「安裝應用程式」選項，也無法離線使用。

建議：補上 `manifest.webmanifest`、完整 icon、service worker 與離線快取；若暫時不做 PWA，則將文案改成「加入主畫面捷徑」。

### P2：正式環境不應使用即時 CDN 編譯

目前使用 Tailwind CDN 與 Babel Standalone，瀏覽器 console 會出現 production warning。

原因位置：[index.html:18](/Users/allen365apple/Desktop/Claude-workspace/projects/聚餐友善分帳機/index.html:18) 與 [index.html:23](/Users/allen365apple/Desktop/Claude-workspace/projects/聚餐友善分帳機/index.html:23)。

建議：改用正式建置流程預先編譯 JSX 與 Tailwind，並鎖定或自行託管必要資源，降低 CDN 失效造成整個工具無法使用的風險。

### P2：計算機應避免動態函式執行

目前使用 `new Function()` 計算運算式。雖然已限制可輸入字元，但仍建議改成簡單的安全運算解析器，並明確處理除以 0、連續運算子與不完整運算式。

原因位置：[index.html:230-231](/Users/allen365apple/Desktop/Claude-workspace/projects/聚餐友善分帳機/index.html:230)。

## 五、建議修正順序

1. 修正 0 人分攤導致金額消失。
2. 修正尾差分配，確保個人加總等於總額。
3. 修正千分位匯入與金額正負值驗證。
4. 修正剪貼簿成功判斷。
5. 加入匯入預覽與錯誤提示。
6. 加入資料暫存／恢復。
7. 補強無障礙、PWA 與正式建置流程。
