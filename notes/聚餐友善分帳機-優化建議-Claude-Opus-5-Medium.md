# 聚餐友善分帳機 — 優化建議清單

**檢查對象**：`index.html`（單檔 561 行，React + Tailwind via CDN）
**檢查日期**：2026-09-15
**檢查方式**：讀完整份程式碼 + 在瀏覽器實際跑一輪（4 人、7 行帳單）
**撰寫者**：Claude Opus 5（Medium）

---

## 一、實測發現的問題（有畫面證據）

### 🔴 1. 匯入功能有三個錯，誤差最大

實測輸入這 7 行：

```
元盅雞湯 180
宮保雞丁 180
可樂 2杯 70
服務費 88
清潔費 100
折扣 -50
小計 350
```

實際匯入結果：

| 原始行 | 匯入成 | 判定 |
|---|---|---|
| 元盅雞湯 180 | **盅雞湯** $180 | ❌ 菜名被砍字 |
| 宮保雞丁 180 | 宮保雞丁 $180 | ✅ |
| 可樂 2杯 70 | 可樂 2杯 $70 | ✅ |
| 服務費 88 | **服務費 $88（變成一道菜）** | ❌ |
| 清潔費 100 | 清潔費 $100 | ⚠️ 會被再加 10% |
| 折扣 -50 | **折扣 $50** | ❌❌ 折價變加價 |
| 小計 350 | （擋掉） | ✅ 黑名單有效 |

**結果**：這桌算出 **$845**，正確應為 **$668**（食物 530 + 服務費 88 + 清潔費 100 − 折扣 50）。
**誤差 $177，方向是多收。**

三個成因：

1. **負號被吃掉** — 抓金額的規則不收負數，`-50` 的負號被丟棄後剩 `50`，變成加收。
   → 修法：偵測到負號要保留，或明確把折扣類項目做成「折抵」欄位。
2. **黑名單不夠** — 目前只擋「小計／總計／Total／找零／合計／TAX／電話／統編／地址／發票」，**沒擋「服務費」「清潔費」「低消」「服務料」**。服務費被當成一道菜均分，第 3 步又整體加 10% → 服務費收兩次還被加成。
   → 修法：黑名單補上這些詞；或更好的做法是辨識到「服務費」時自動去設定服務費率，而不是當成菜。
3. **「元」字全域替換** — 為了清掉「180元」的「元」用了全域替換，導致菜名裡的「元」也被砍。實測「元盅雞湯」→「盅雞湯」。同理「元氣豬排」會變「氣豬排」。
   → 修法：只清掉金額結尾的「元」，不要動菜名。

---

### 🔴 2. 中途加人 → 顯示「大家都有」但新人沒被算進去

實測步驟：先輸入菜 → 回上一步按「新增朋友」加了朋友 4 → 回到第 2 步。

實際狀況：

- 「高麗菜」那道菜的「全選」按鈕**仍是亮綠色**（看起來大家都有），但朋友 4 的名字是灰的（未分攤）→ **畫面在騙人**
- 結算時朋友 4 = **$184**，其他三人 $220 ← 他確實被漏掉
- 上方「這道菜誰有吃」還停在 **「3 人分攤」**，朋友 4 沒被自動勾選 → **之後新輸入的每一道菜也都會繼續漏掉他**

最後一點最嚴重，因為它不是單筆錯誤，是會一直錯下去。

→ 修法：新增成員時，把原本標記為「大家都有」的項目同步加入新人；同時把新人補進當前的分攤名單。

---

### 🔴 3. 尾差 — 每人金額加起來 ≠ 帳單金額

實測 3 人均分一道 100 元 + 10% 服務費：

| 畫面顯示 | 金額 |
|---|---|
| 總金額 | **$110** |
| 朋友 A | $37 |
| 朋友 B | $37 |
| 朋友 3 | $37 |
| 三人加總 | **$111** |

多收 $1。人多菜多時會累積到 3～5 元，方向不固定（有時多收有時少收）。

成因：每個人的金額各自四捨五入，總金額另外獨立四捨五入，兩邊不對齊。

→ 修法：算完每人金額後，把尾差塞給其中一人（通常是先付錢的那位），保證加總等於帳單金額。

---

### 🟡 4. 標題列遮住輸入區

實測往下滑時，白色的「聚餐友善分帳機」標題列直接壓在輸入卡片上，品項欄和金額欄整個被遮住，只露出「全選／一般／吃素」被切一半的那排。

成因：主標題列和第 2 步的輸入卡片都設定黏在畫面最頂端（同一個位置），輸入卡片的層級較低所以被壓在下面。

→ 修法：輸入卡片的黏著位置往下讓開一個標題列的高度。

## 二、讀程式碼確認、但未實際重現的問題

### 🔴 5. 重新整理資料全失

程式裡沒有任何存檔機制（搜過 `localStorage`，零筆），資料只存在記憶體。

**設計上的自我矛盾**：這支 App 的主打功能是「拍帳單 → 切去 ChatGPT 轉文字 → 貼回來」，但手機切 App 回來若被系統清掉背景，整頁就是一張白紙，前面輸入的全部消失。

→ 修法：加自動存檔（20 行內可完成），順便補一顆「重新開始」按鈕（現在想清空只能重新整理）。

> 註：此項為讀程式碼確認「確實沒有存檔機制」，非實際重現過資料消失。

### 🟡 6. 服務費只能 5% 一跳

目前只能 0/5/10/15…。實務上有店家收 3%、5%，也有**固定加收清潔費 100 元**這種不該乘百分比的項目。

→ 修法：讓費率可直接輸入；另外增加「固定金額加收」欄位。

### 🟡 7. 標籤沒人時按了沒反應

若某個標籤（如「🥦 吃素」）的成員都被刪掉，按那顆標籤會變成 0 人分攤，「加入清單」直接變灰但**不告訴你為什麼**。修改既有項目時有提示，新增時沒有。

→ 修法：新增時也給同樣的提示。

## 三、加值建議（不是錯誤，但會讓人想一直用）

### ⭐ 8. 缺「誰先付錢 → 誰要轉多少給誰」

實務上都是一個人先刷卡、其他人事後轉帳。現在只輸出「每人應付 $X」，還要自己在腦中換算誰欠誰。

加一個「付款人」選項，結算單就能直接輸出：

```
小明 → 轉 $250 給柏文
小華 → 轉 $180 給柏文
```

貼群組一目了然。**這是最值得加的一個功能**，也順便解決尾差該塞給誰的問題。

### 9. 一個人吃兩份只能輸入兩次菜

可考慮在名字上加「×2」的份數權重。

### 10. 手機首次開啟會白屏一兩秒

目前用瀏覽器即時編譯（Babel standalone）+ unpkg CDN。好處是單檔好改，代價是每次開都要重新編譯 56KB，而且 unpkg 在台灣偶爾連不上時**會整頁空白、沒有任何錯誤訊息**。

→ 若要拿給朋友用，建議換成較穩的 CDN，並加一個載入失敗的提示。

### 11. Android 的「安裝應用程式」其實不會出現

少一個 `manifest.json`，所以 Chrome 只會給「加入主畫面」，跟安裝教學的文字不完全一致。補一個小檔案就能變成真正的 PWA。

## 四、建議修正順序

| 順序 | 項目 | 理由 |
|---|---|---|
| 1 | 匯入的三個錯（#1） | 實測誤差 $177，最嚴重 |
| 2 | 中途加人（#2） | 會一直錯下去，且畫面騙人 |
| 3 | 尾差（#3） | 分帳機最不該錯的基本功 |
| 4 | 自動存檔（#5） | 跟主打功能衝突 |
| 5 | 標題列遮擋（#4） | 順手一起修 |
| 6 | 付款人 → 轉帳指示（#8） | 當 v2 的主打功能 |

前 3 項修完，就是一支可以安心拿出去用的工具。

## 五、原本判斷錯、實測後更正的一項

初次只讀程式碼時，我判斷「負數折扣會被忽略，所以總額會算多」。

**實測後發現判斷錯誤**：負號不是被忽略，而是被吃掉——`折扣 -50` 變成 `折扣 $50`，**折價直接變成加價**。一筆就差 100 元，比原本的判斷嚴重。

保留這段紀錄，是為了標示「只讀程式碼」與「實際跑過」的差別。
